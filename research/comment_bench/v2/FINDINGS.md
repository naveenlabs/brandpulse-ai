# Comment Bench v2 — Findings

> **Superseded, 28 Aug 2026.** This document records a bench of **three** models. Seven more
> were added the same day and all ten were re-evaluated against the 350 human labels. The
> winner is unchanged (`cardiffnlp/twitter-roberta-base-sentiment-latest`), and it has now
> been **adopted into `pipeline/comment_module.py`**. For the current, complete result see
> [`HUMAN_GROUND_TRUTH_EVALUATION.md`](HUMAN_GROUND_TRUTH_EVALUATION.md).
> The findings below remain accurate as of their own date and are kept as a dated record.


**Date:** 27 Aug 2026
**Corpus:** 10 YouTube review videos, 4,843 comments (relevance-ordered) + 4,852 comments
(time-ordered) = **9,695 comments scored**
**Models:** cardiffnlp/twitter-roberta-base-sentiment-latest, tabularisai/multilingual-sentiment-analysis, VADER
**Status:** human labelling not yet started. **No accuracy claim appears in this document.**

Everything below was measured on this project's own data. Every number is traceable to
`analysis/unlabelled_analysis.json` or `analysis/fetch_order_comparison.json`, both of which
are regenerated by scripts in this directory.

---

## 0. Why v2 exists

The v1 bench (`comment_bench/`) hand-labelled 120 comments across 12 videos and found
cardiffnlp 68.3% / tabularisai 58.3% / VADER 58.3%. Three problems with using that as a
decision:

1. **n = 120.** No confidence interval and no significance test were ever computed, so it was
   never established that the 10-point gap was larger than noise.
2. **One rater.** No inter-rater agreement, so the ground truth itself was unvalidated.
3. **Only the winning label was stored.** A confident prediction and a near-coin-flip were
   recorded identically, making calibration analysis impossible without re-running everything.

v2 fixes all three by design, and adds a frozen corpus so results stop moving between runs.

## 1. Method

| Stage | Script | Output |
|---|---|---|
| Freeze corpus | `fetch_corpus.py` | `corpus/`, `corpus_time/` |
| Score all models | `run_models.py` | `scored/`, `scored_time/` |
| Draw label samples | `build_label_sheet.py` | `labels/` |
| Pre-label analysis | `analyse_unlabelled.py` | `analysis/unlabelled_analysis.json` |
| Fetch-order test | `compare_fetch_order.py` | `analysis/fetch_order_comparison.json` |

**Frozen corpus.** `PROTOTYPE_FINDINGS.md` §5 traced the pipeline's run-to-run score
instability to a live re-fetch: a one-comment shift (35/29/36 → 36/28/36) flipped a
video-level label, which is injected into all 77 segment prompts. Fetching once and freezing
removes that trigger entirely.

**Full distributions stored.** For every comment we now keep each model's probability over
all three classes, plus tabularisai's raw 5-class output before the project's 5→3 collapse,
plus VADER's *signed* compound score before thresholding. v1 stored `abs(compound)`, which
discarded the sign and made threshold tuning impossible.

**Measured inference cost** (4,843 comments, Apple MPS): cardiffnlp 88.0 s (18.2 ms/comment),
tabularisai 62.9 s (13.0 ms/comment), VADER 0.4 s (0.1 ms/comment). No runtime figures existed
anywhere in this repo before now.

**Sampling for labelling.** Sample A (n=300, 30 per video, simple random) is the only sample
any accuracy figure may be computed on. Sample B (n=50, drawn from three-way model
disagreements) is deliberately enriched with hard cases for failure-mode analysis and its
accuracy is meaningless by construction. A 100-comment subset of Sample A goes to a second
rater for Cohen's kappa. Sheets contain text only — no model output, no confidence, no
agreement flags. Rubric fixed in advance in `labels/GUIDELINES.md`, written before any label
was entered so ground truth cannot be tuned after seeing model performance.

**Reproduce.** From `brandpulse_ai/`, with the venv active:

```bash
python research/comment_bench/v2/fetch_corpus.py --limit 500
python research/comment_bench/v2/fetch_corpus.py --limit 500 --order time
python research/comment_bench/v2/run_models.py
python research/comment_bench/v2/run_models.py --corpus-dir comment_bench/v2/corpus_time \
                                      --out-dir    comment_bench/v2/scored_time
python research/comment_bench/v2/build_label_sheet.py
python research/comment_bench/v2/analyse_unlabelled.py
python research/comment_bench/v2/compare_fetch_order.py
```

The fetch steps hit the YouTube API and will return a *different* corpus on a later date, since
comments accrue. That is precisely why the corpus is frozen to disk: the files in `corpus/` and
`corpus_time/`, not the fetch command, are the reproducible artefact. Every stage after fetching
is deterministic and reproduces exactly from those files (fixed seed 42, no model sampling).

## 2. Finding — the three models do not agree on what this corpus says

Same 4,843 comments, relevance-ordered:

| Model | POSITIVE | NEUTRAL | NEGATIVE |
|---|---:|---:|---:|
| cardiffnlp | 44.8% | 35.5% | 19.7% |
| tabularisai | 33.2% | 31.1% | **35.6%** |
| VADER | **61.2%** | 23.8% | 15.1% |

Pairwise agreement:

| Pair | Raw agreement | Cohen's kappa |
|---|---:|---:|
| cardiffnlp vs tabularisai | 62.2% | 0.435 |
| cardiffnlp vs VADER | 61.7% | 0.373 |
| tabularisai vs VADER | 49.0% | 0.237 |

**All three agree on only 40.9% of comments.**

tabularisai reports NEGATIVE as the largest class; VADER reports 61.2% POSITIVE. These are
not small calibration differences, they are different accounts of the same audience. Which one
is right cannot be settled here — that requires the ground truth now being labelled.

## 4. Finding — the fetch order alone changes the verdict on 11 of 30 video-model combinations

`pipeline/comment_module.py` fetches with `order="relevance"`. To test whether that choice
biases the result, an independent 500-comment sample of the same ten videos was frozen with
`order="time"` and scored identically.

| Measure | Result |
|---|---|
| Mean sentiment shift (time − relevance), full sample | **−0.2089**, negative on **10/10** videos |
| Mean sentiment shift, restricted to the shared date window | **−0.2203**, negative on **10/10** videos |
| Video-level verdicts changed by fetch order alone | **11 / 30** combinations |

Corpus-level label share under cardiffnlp:

| Ordering | POSITIVE | NEUTRAL | NEGATIVE |
|---|---:|---:|---:|
| relevance (what the pipeline uses) | 44.8% | 35.5% | 19.7% |
| time | 32.5% | 35.6% | 31.9% |

The recency explanation is ruled out: recomputing within the date window the two samples share
gives a slightly *larger* effect (−0.2203) than the unrestricted comparison, and the direction
is unanimous across all ten videos.

**Interpretation.** BrandPulse AI's comment channel, as currently implemented, measures a
systematically more positive slice of the audience than a chronological sample of the same
videos would. The effect is roughly 0.22 on a [−1, +1] scale and it is consistent, not noisy.

**What is not established:** *why*. The relevance sample is far more engaged (on the AirPods
Max video, median 48 likes versus 0 for the time sample), so engagement selection is the
obvious candidate. But the correlation between likes and sentiment **reverses sign between the
two corpora** (relevance r = −0.105, time r = +0.066, both n ≈ 4,850), because like count is
confounded with comment age. No mechanism is claimed. The effect itself is measured directly
and does not depend on explaining it.

## 5. Finding — more comments halves verdict instability but does not fix it

Bootstrap, 2,000 resamples per video-model, measuring how often the video-level verdict
differs from the verdict on the full sample:

| Model | Flip rate at n=100 | Flip rate at n=500 |
|---|---:|---:|
| cardiffnlp | 18.1% | 10.5% |
| tabularisai | 30.0% | 11.6% |
| VADER | 0.0% | 0.0% |

Moving from 100 to 500 comments cuts instability by roughly half for cardiffnlp and by about
two-thirds for tabularisai. That justifies the 500-per-video decision with a measured number.

But it does not solve the problem. Per-video, the residual instability tracks the margin:

| Video | Model | Verdict | Margin | Flip rate at n=500 |
|---|---|---|---:|---:|
| Bleu de Chanel | cardiffnlp | POSITIVE | 0.003 | **48.9%** |
| MacBook Air M5 | cardiffnlp | POSITIVE | 0.012 | **40.6%** |
| Pixel 10 Pro | tabularisai | POSITIVE | 0.024 | 26.7% |
| Nothing Phone 3 | tabularisai | NEGATIVE | 0.026 | 23.3% |
| Apple Vision Pro | cardiffnlp | POSITIVE | 0.240 | 0.0% |

Where the top two classes are within a few percent of each other, the verdict is close to a
coin flip no matter how many comments are fetched. **The fragility is caused by the discrete
majority-vote rule, not by sample size.** `PROTOTYPE_FINDINGS.md` §5 proposed replacing it
with a continuous weighted score as future work; this is the measurement that justifies doing
so. VADER's 0.0% is not a virtue — it is so positively skewed that its margins are never close.

## 6. Finding — like-weighted aggregation is not safe to adopt yet

Weighting each comment by `1 + log(1 + likes)` changes the video-level verdict in **4 of 30**
video-model combinations, including cardiffnlp POSITIVE → NEUTRAL on two videos. So engagement
weighting is not cosmetic.

However, given §4 — the likes-sentiment correlation reverses sign between the two corpora —
like-weighting would push the score in **opposite directions** depending on which sample was
drawn. Adopting it on intuition would be exactly the kind of untested model decision this bench
exists to eliminate. It needs ground truth first.

## 7. Finding — the 5→3 collapse discards little, and VADER's threshold is not the problem

**tabularisai raw 5-class argmax** across 4,843 comments:

| Raw class | n | % | Collapses to |
|---|---:|---:|---|
| Neutral | 1,630 | 33.7% | NEUTRAL |
| Negative | 1,446 | 29.9% | NEGATIVE |
| Positive | 1,167 | 24.1% | POSITIVE |
| Very Positive | 386 | 8.0% | POSITIVE |
| Very Negative | 214 | 4.4% | NEGATIVE |

Only 12.4% of comments land in an intensity bucket, so the 5→3 rule is not where
tabularisai's negativity comes from — plain "Negative" alone accounts for 29.9%.

**VADER threshold sweep** (label share only; which threshold is best needs ground truth):

| Threshold | POSITIVE | NEUTRAL | NEGATIVE |
|---|---:|---:|---:|
| 0.05 (standard) | 61.2% | 23.8% | 15.1% |
| 0.20 | 57.6% | 30.0% | 12.3% |
| 0.50 | 38.2% | 56.8% | 5.1% |

Even at 0.50 VADER still calls 38.2% positive against 5.1% negative. Its positive skew is not
a threshold artefact.

## 8. Temporal drift — measured, inconclusive

Splitting each video's relevance-ordered comments into age quartiles gives a mean Q4−Q1
sentiment change of **+0.104**, falling on only 4 of 10 videos. No consistent direction.

This is not evidence that sentiment is stable over time. A relevance-ordered sample is not a
time series, and §4 shows relevance selection is itself biased. Testing drift properly needs a
chronological sample with a much wider date span than the 500 most recent comments.
**Recorded as inconclusive rather than reported as a result.**

## 9. What this bench cannot yet say

No accuracy figure. No statement about which model is better. Both require the human labels
now in `labels/`. Once those exist, stage 4b computes:

- Accuracy on Sample A with Wilson confidence intervals
- **McNemar's test** on the paired disagreements — the test that was never run in v1
- Per-class precision, recall, F1 and confusion matrices
- **Cohen's kappa between the two human raters**, so the ground truth itself carries a quality figure
- Calibration: is a wrong model confident or uncertain, now answerable from the stored distributions
- The best VADER threshold, and whether an alternative tabularisai 5→3 rule beats the current one

## 10. Limitations

- **Domain narrow.** 5 smartphones, 2 audio, 1 laptop, 1 XR headset, 1 fragrance. The set was
  chosen for comment volume, which was the right priority, but it is not a test of
  generalisation across product categories.
- **All English.** tabularisai's headline advantage is multilingual coverage. This corpus
  cannot test it, so that claimed strength stays untested here.
- **Top-level comments only.** Replies are excluded. The API's `commentCount` includes them,
  which is why 22,968 reported comments yields 500 top-level.
- **Relevance ranking is a black box.** §4 measures its effect but cannot decompose it.
- **500 per video is a cap, not a census.** Nine videos have far more; the cap exists so no
  single video dominates the result.
- **Bootstrap assumes the fetched sample represents the video.** Given §4, that assumption is
  itself questionable for the relevance corpus, which is a further argument for continuous
  scoring over majority vote.

## 11. Open items

1. **Human labelling.** 350 comments (rater 1) and the 100-comment overlap (rater 2). Blocks
   every accuracy claim.
2. **Step 6 of the bench method (adopt the winner) remains unsatisfied.** `pipeline/comment_module.py:37` still loads
   tabularisai. It stays there until v2 produces a properly tested winner — swapping on v1's
   untested 68.3% would repeat the mistake this bench exists to correct.
3. **Replace majority-vote aggregation with a continuous score**, per §5 and
   `PROTOTYPE_FINDINGS.md` §5. Justified by measurement now, not by intuition.
4. **Decide what the pipeline should fetch.** §4 shows `order="relevance"` biases the result
   positive. Changing it is a design decision with a real effect on every score the system
   produces, and it should be made deliberately and written up, not left as a default.
